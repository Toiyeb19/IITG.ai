# IITG.ai

Predictive Paradox: Grid Demand Forecasting
Text Summary Report

This project predicts the next hour's electricity demand (`demand_mw` at $t+1$) on the national grid using only information available up to time $t$. In strict adherence to the project constraints, deep learning architectures and autoregressive packages are avoided, and a robust classical machine learning pipeline using **XGBoost** is applied.

---

## 📊 Dataset Description
The model integrates three distinct data sources, aligning multiple frequencies into a unified, hourly structure:
* **Grid Demand Data (`PGCB_date_power_demand.xlsx`):** Hourly power generation and demand patterns.
* **Weather Data (`weather_data.xlsx`):** Hourly environmental factors including temperature, apparent temperature, humidity, and precipitation.
* **Macroeconomic Data (`economic_full_1.csv`):** Annual World Bank development indicators, tracking broad economic variables such as annual GDP growth.

## Methodology & Pipeline

### 1. Anomaly Handling & Data Cleaning
* **Spike Mitigation:** Severe, undocumented recording spikes and extreme outliers in the raw demand series were detected and smoothed using a robust rolling 3-sigma bound strategy ($\mu \pm 3\sigma$). 
* **Missing Value Imputation:** Missing fields were imputed safely. Initial `NaN` boundary gaps generated by long historical lookbacks were strictly dropped rather than backfilled (`bfill`) to rigorously prevent forward-looking bias.

### 2. Temporal Feature Engineering
Because tabular tree regressors process records independently (non-sequential modeling), the concept of time was entirely re-established using deterministic lookback structures:
* **Seasonal Historical Offsets:** Tracks core demand values exactly 24 hours ago (`demand_lag_24h`) and 1 week ago (`demand_lag_168h`) to represent cyclical load baselines.
* **Lookback-Safe Moving Aggregates:** Created rolling statistics (including 3-hour and 24-hour moving means and standard deviations). These were strictly calculated over shifted series to guarantee no real-time leakage.
* **Diurnal Calendar Flags:** Extracted integer indicators for explicit time properties, including `hour`, `month`, `day_of_week`, and `is_weekend`.

### 3. Macroeconomic Integration
To properly layer wide-format annual growth indicators into the long-format hourly framework without introducing data leakage, macro variables were systematically matched using a single-year shift offset (`merge_year = year + 1`). This ensures that the training framework only influences current hourly patterns using an established, previously reported economic baseline.

### 4. Leakage-Free Chronological Split
The tabular dataset was chronologically ordered before defining the modeling target via a forward shift operation (`target_demand_next_hour = demand_mw.shift(-1)`). The validation matrix was partitioned strictly along a historical date boundary (Train: Pre-2024, Test: All of 2024) to accurately evaluate model generalization across a realistic out-of-time operation interval.

## Leakage & Autocorrelation

### The Data Leakage Discovery
During initial pipeline development, the model achieved an ultra-low, highly optimistic validation score of **~2.58% MAPE**. However, evaluating the model's Feature Importance (Information Gain) revealed that the tree-based architecture was heavily exploiting concurrent target proxies:

* **Direct Leak (`demand_mw`):** The model was inadvertently using the current hour's exact real-time demand ($y_t$) to guess the next hour's demand ($y_{t+1}$).
* **Proxy Leak (`generation_mw`):** Because power grids maintain a near 1:1 instantaneous equilibrium between supply and consumption to maintain system stability, generation metrics served as a perfect mirror proxy for target demand.
* **Autocorrelation Trap (`demand_lag_1h`):** The model hyper-focused on time series inertia, effectively turning a powerful gradient-boosted tree regressor into a basic persistence "copy-paste" machine.

>  **Why High Autocorrelation & Target Proxies Are Dangerous:**
> When a model over-relies on instant lags ($t-1$) and concurrent indicators, it masks its inability to map the structural physics of the system. If a sudden grid blackout, severe weather shift, or load-shedding anomaly occurs, the model breaks down instantly in production because it never learned the underlying causal drivers (like climate dynamics or diurnal human behavior).

### The Fix
To force the model to unravel the true *Predictive Paradox* and learn systemic structural relationships rather than simple trend extrapolation, the pipeline was aggressively hardened:
1. **Purged Concurrent Proxies:** `demand_mw`, `generation_mw`, and operational variables were completely removed from the feature matrix ($X$).
2. **Eliminated Brittle Lags:** Dropped `demand_lag_1h` and `demand_lag_2h` to decouple the pipeline from short-term time series inertia.
3. **Enforced Lookback Discipline:** Shifted short-term moving metrics safely into the past (`past_demand = demand_mw.shift(1)`), ensuring a true lookback aggregate window (`roll_mean_3h`) with zero future insight.

## Modeling, Results & Interpretation

### Algorithm: XGBoost Regressor
XGBoost was chosen for its exceptional ability to capture non-linear, multi-variable thresholds (e.g., how both extreme cold and extreme heat cause distinct power spikes via HVAC systems) and its capacity to maximize structural splits using Information Gain.
* **Hyperparameters:** `n_estimators=500`, `learning_rate=0.05`, `max_depth=6`, `objective='reg:squarederror'`, `random_state=42`

### Evaluation Metric
The final models were rigorously benchmarked on the chronological 2024 hold-out test split using Mean Absolute Percentage Error (MAPE).
